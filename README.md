# TURAS Survey

TURAS 로그인과 분리해 운영하는 외부 설문 페이지입니다. 공용 설문과 기업·과제·계약별 맞춤형 설문을 모두 지원합니다.

## 구조

```txt
기업 접속
→ Vercel 설문 페이지
→ /api/submit
→ 우리 서버 /api/survey/submit
→ 우리 서버 DB 저장
```

## 포함 기능

- 무기명 설문 응답 화면
- 기업·과제·계약별 개별 토큰 링크
- 메일로 안내한 계약ID를 입력해 계약정보를 확인한 뒤 설문 시작
- 조사대상 엑셀 열을 연결하는 맞춤정보 표시 블록
- 블록별 표시항목·항목명·순서·섹션·문항 앞뒤 위치 설정
- 앞 문항의 응답에 따른 문항·섹션 조건부 표시(복수 기준 문항 OR/AND 분기)
- 섹션·개별 문항별 안내파일 업로드 및 응답자 보기·다운로드
- 문항 사이에 배치하는 안내·자료 블록(설명·이미지·파일만 표시, 응답 미수집)
- 설문 마지막 단계의 응답자용 자료 1개 업로드·다운로드
- 실제 등록된 조사대상 1건을 이용한 설문 제작 화면 미리보기
- KEITI 보유 기업정보(1-1) 및 기술실시계약 정보(1-3) 확인·정정
- 조사대상 엑셀 일괄 등록 및 개별 링크 엑셀 생성
- 제출 완료 화면
- 종료 안내 화면
- Vercel API Route를 통한 우리 서버 저장 API 중계
- 환경변수 기반 마감일/저장 API 설정
- 공용 무기명 설문에서는 기업명, 사업자번호, 과제번호, 담당자명 등 식별정보 미수집

## 배포 순서

1. GitHub 새 저장소 생성
2. 이 프로젝트 전체 파일 업로드
3. Vercel에서 GitHub 저장소 Import
4. 환경변수 등록
5. Deploy

## Vercel 환경변수

```env
NEXT_PUBLIC_DEFAULT_SURVEY_ID=nipa_ai_ict_2027
SURVEY_API_URL=https://your-server.example.com/api/survey/submit
SURVEY_API_KEY=server-secret-key
SURVEY_END_AT=2027-12-31T23:59:59+09:00
ALLOW_RESPONSE_TOKEN_HASH=false
TOKEN_HASH_SECRET=
```

`TOKEN_HASH_SECRET`은 맞춤형 설문 링크 검증에 사용됩니다. 운영환경에서는 32자 이상의 무작위 값으로 반드시 설정해야 합니다. 예: `openssl rand -hex 32`

## 우리 서버 API 규격

Vercel `/api/submit`은 아래 형식으로 우리 서버에 전달합니다.

```json
{
  "survey_id": "nipa_ai_ict_2027",
  "response_id": "uuid",
  "submitted_at": "2027-05-01T12:00:00.000Z",
  "answers": {
    "q1": "응답값",
    "q2": ["선택1", "선택2"],
    "q3": "장문 응답"
  },
  "meta": {
    "source": "vercel-survey",
    "version": "1.0.0"
  }
}
```

Authorization 헤더:

```http
Authorization: Bearer <SURVEY_API_KEY>
```


## 9. 설문 생성 화면

임시 관리자용 설문 생성 화면이 포함되어 있습니다.

```txt
/admin/builder
```

이 화면에서 작성한 설문은 Firebase에 저장되며, 저장된 설문을 다시 불러와 수정할 수 있습니다.

가능한 작업:

- 설문 기본정보 수정
- 섹션 추가/삭제
- 문항 추가/삭제
- 작성한 문항 블록을 위·아래로 순서 이동
- 문항 ID 중복 방지 및 기존 중복 문항 ID 자동 보정
- 문항 유형 변경
- 선택지 수정
- 문항 및 섹션 조건부 표시 설정
- 조건별 기준 문항·답변 추가 및 `하나라도 충족(OR)`·`모두 충족(AND)` 연결
- 섹션 및 개별 문항에 PDF·한글·Office·ZIP 안내파일 등록
- `+ 안내·자료 블록`으로 답변 입력칸 없는 설명·다운로드 영역 추가
- 마지막 단계에 표시할 응답자 다운로드 자료 1개 등록
- 맞춤정보 표시 블록 추가·삭제
- 업로드 열별 표시 여부·순서·화면 명칭 설정
- 맞춤정보 블록의 섹션 및 문항 앞뒤 배치
- 등록한 조사대상 자료로 미리보기
- 미리보기

주의:

- 운영 단계에서는 `/admin/builder` 접근을 제한하거나 별도 관리자 인증을 붙이는 것이 좋습니다.
- 섹션 분기는 분기 기준 문항보다 뒤에 있는 섹션에서 설정합니다. 응답 화면의 단계 수와 진행률에는 실제 표시되는 섹션만 포함되며, 숨겨진 섹션의 필수문항과 응답값은 제출에서 제외됩니다.
- 복수 조건의 기본값은 `하나라도 충족(OR)`입니다. 예를 들어 `S2=과거 매출 후 현재 중단` 또는 `S4=사업화 중단`을 각각 조건으로 추가하면 둘 중 하나만 선택되어도 S5를 표시합니다. `모두 충족(AND)`을 선택하면 모든 조건이 동시에 맞을 때만 표시됩니다.
- 응답자 다운로드 자료는 설문 기본정보에서 1개를 등록할 수 있으며, 마지막으로 표시되는 섹션 하단에 나타납니다. 파일은 최대 50MB입니다.
- 섹션·문항 안내파일은 각 항목당 최대 10개, 파일당 최대 50MB까지 등록할 수 있습니다. 응답자는 설문 화면에서 새 창으로 열거나 내려받을 수 있습니다.
- 문항 순서 이동은 문항의 배열 위치를 기준으로 처리합니다. 예전에 저장된 설문에 중복 문항 ID가 있으면 불러올 때 중복 ID를 자동 보정합니다.
- 맞춤형 설문의 공용 응답자 링크에는 계약ID 입력 화면이 먼저 표시됩니다. `?t=`가 포함된 개별 링크는 계약ID 입력을 건너뜁니다.
- 응답 수정 코드 기능은 사용하지 않습니다. 맞춤형 링크는 조사대상별 1회 제출만 허용합니다.

## 맞춤형 설문 운영

1. `/admin/builder`에서 설문을 불러옵니다.
2. `기업·과제별 맞춤형 설문`을 켭니다.
3. `맞춤정보 표시 블록`의 `엑셀 열 불러오기`를 눌러 실제 조사대상 파일을 선택한 후 목록에 넣을 열만 고릅니다. 계약ID·과제번호·기업명은 조회용 필수 열로 자동 선택됩니다.
4. 선택한 열의 표시 여부·응답자용 명칭·기업/계약 블록·순서를 설정한 뒤 설문을 저장합니다. 원본 엑셀 열명은 데이터 연결 기준이므로 화면에서 직접 바꾸지 않습니다.
   계약정보 블록에서는 일치 여부 선택지와 정정 입력란 안내 문구도 설문별로 직접 수정할 수 있습니다.
5. 저장한 뒤 `업로드 자료로 미리보기`에서 실제 표시 결과를 확인합니다. 아직 조사대상을 등록하지 않았다면 작성예시 자료가 표시됩니다.
6. `/admin/targets`로 이동합니다.
7. 같은 구조의 조사대상 엑셀을 업로드합니다. 편집 화면에서 연결한 원본 열명을 기준으로 모든 표시값을 읽습니다.
8. 자동 생성된 `기업과제별_설문링크.xlsx`에서 기업별로 동일하게 생성된 `기업 맞춤형 설문링크`와 해당 기업의 계약ID를 안내합니다.
9. 기업 링크에 접속하면 `○○기업 기술이전 설문`이 표시됩니다. 기업은 본인이 응답할 계약ID를 입력하고 해당 계약·과제 정보를 확인한 뒤 설문을 시작합니다. 한 기업에 계약이 여러 건이면 같은 기업 링크에서 계약ID별로 각각 응답합니다.

기존 설문 설정은 자동으로 새 블록 구조로 읽힙니다. 기본값은 기업정보 블록이 첫 번째 섹션의 첫 문항 앞, 기술실시계약 정보 블록이 첫 일반 문항 뒤입니다.

열 위치와 이름은 설문에 저장된 연결 설정을 사용합니다. `조사대상 여부` 열을 연결하면 값이 `조사대상`인 행만 등록됩니다. 원본 엑셀의 연결 열 이름을 바꾼 경우에는 설문 편집 화면에서 `엑셀 열 불러오기`를 다시 실행해야 합니다.

기업ID와 과제ID는 필수입니다. 동일 기업·과제에 계약이 여러 건이면 계약ID도 구분해야 합니다. 같은 조사대상을 다시 업로드하면 새 토큰이 발급되어 이전 링크는 무효화되며, 이미 저장된 응답은 삭제되지 않습니다.

응답 저장 시 화면에 표시한 정보는 `target_snapshot`, 기업의 정정 내용은 `answers`에 분리 저장됩니다.

기업 맞춤형 링크와 계약ID 입력 기능은 조사대상 등록 시 함께 생성되는 해시를 사용하므로, 이 기능을 배포한 뒤에는 기존 대상 엑셀을 `/admin/targets`에서 한 번 다시 등록해야 합니다. 계약ID는 URL에 남기지 않고 확인 후 별도 접근 토큰으로 전환됩니다. `TOKEN_HASH_SECRET`을 바꾸면 기존 기업 링크·계약별 바로가기·계약ID 접속정보가 모두 무효화됩니다.

Windows PowerShell 5.x에서 `TOKEN_HASH_SECRET`을 만들 때는 다음 명령을 사용합니다.

```powershell
$bytes = New-Object byte[] 32
$rng = [Security.Cryptography.RandomNumberGenerator]::Create()
$rng.GetBytes($bytes)
$rng.Dispose()
-join ($bytes | ForEach-Object { $_.ToString("x2") })
```

기존 저장소 위에 파일을 덮어올리는 방식도 지원하도록 `/api/response/load`는 410 응답을 주는 종료 경로로 남겨 두었습니다. 화면에는 응답 수정 코드와 QR이 표시되지 않습니다.

```txt
survey_targets/{target_id}                  조사대상 및 토큰 해시
surveys/{survey_id}/responses/{response_id} 응답, 조사대상ID, 표시정보 스냅샷
```
